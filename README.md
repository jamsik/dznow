# DZNOW

Telegram Mini App: данные → готовый фирменный дизайн → публикация.
Риэлтор вводит цифры по объекту и получает макет 1080×1920 в стиле своего агентства.

```
DZNOW → выбрать задачу → выбрать шаблон → заполнить данные → превью → создать → скачать
```

## Что внутри

```
web/                 фронтенд Mini App (Vite + React)
  index.html         приложение
  render.html        «голая» страница с одним макетом — её снимает сервер
  src/
    templates/       макеты 1080×1920: StoryCanvas + RealtyCard + RealtyFigure
    components/      переиспользуемый UI: превью, форма, загрузчик, бренд, навигация
    pages/           Home · Editor · Render · Result · Projects · Profile
    data/            каталог сценариев, схема полей, бренд агентства
    lib/             формат чисел и ипотека, Telegram SDK, слой api, экспорт PNG
    styles/          app.css (дизайн-система) + story.css (макеты)
api/                 FastAPI + SQLite + рендер PNG на Playwright
prototype/           одностраничный HTML-прототип, запускается без сборки
```

**Главный принцип:** превью в приложении и файл на выходе рисует **один и тот же
компонент** `StoryCanvas`. Сервер открывает `render.html` в headless-Chromium и снимает
скриншот. Никакой второй вёрстки «для рендера» не существует — иначе неизбежно
расхождение «в приложении было красиво, скачал другое».

## Запуск

Локально — ниже. На сервере, в Telegram, по кнопке бота — **[DEPLOY.md](DEPLOY.md)**:
Docker, GitHub, https и подключение бота к авторизации, по шагам.

### В один клик

В корне лежит **«Запустить DZNOW.bat»** — двойной клик, и он сам:

* проверит, что в PATH есть `node`, `npm` и `python`;
* при первом запуске поставит зависимости фронта и создаст `web\.env`;
* откроет два окна — «DZNOW WEB» (Vite, 5173) и «DZNOW API» (uvicorn, 8010);
* дождётся, пока порты реально ответят, и откроет браузер на <http://127.0.0.1:5173/>.

Запускать можно сколько угодно раз: занятый порт считается уже поднятым сервисом,
второе окно для него не открывается. Остановить — закрыть оба окна.

Вся логика в `tools\launch.ps1`; сам `.bat` — только запуск PowerShell,
потому что cmd.exe калечит UTF-8 внутри батников, а PowerShell — нет.
Ниже то же самое руками — пригодится, когда что-то не поднялось.

### Фронтенд

```bash
cd web
npm install
npm run dev            # http://127.0.0.1:5173
```

Без бэкенда приложение полностью кликабельно: проекты лежат в localStorage,
картинка собирается на устройстве (`html2canvas`). Это режим `isMock` в `src/lib/api.js`.

### Бэкенд (Windows, обычная командная строка)

```bat
cd F:\DZNOW\api
pip install -r requirements.txt
python -m playwright install chromium   :: один раз: свой Chromium для рендера
run.bat                                  :: http://127.0.0.1:8010
```

`.env` не обязателен: пока `BOT_TOKEN` пуст, вход анонимный, а `RENDER_URL`
по умолчанию смотрит на дев-сервер фронта. Понадобится что-то поменять —
`copy .env.example .env` (в PowerShell `Copy-Item`, в bash `cp`), приложение
подхватит файл само.

**Порядок запуска важен:** сначала `npm run dev` (фронт на 5173), потом API.
Рендер-воркер открывает страницу фронта, поэтому без него рендерить нечего.

Чтобы фронт пошёл на сервер, скопируйте `web\.env.example` в `web\.env`:

```
VITE_API_BASE=/api
```

и перезапустите `npm run dev` — Vite читает `.env` только при старте.
Он же проксирует `/api` и `/files` на `127.0.0.1:8010`, так что CORS в деве не мешает.

Проверить, что живо: <http://127.0.0.1:8010/api/health> отдаёт `{"ok":true}`.

### Если pip падает на greenlet

```
error: Microsoft Visual C++ 14.0 or greater is required
```

Это Python 3.14: у `greenlet` под него ещё нет готового колеса, и pip лезет его
компилировать. Лечится обновлением зависимостей (в `requirements.txt` версии уже
не прибиты) — `pip install -r requirements.txt --upgrade`.

Если и свежий playwright тянет несобираемый greenlet, поднимите API на Python 3.12
в отдельном окружении — остальная система при этом не трогается:

```bat
winget install Python.Python.3.12
cd F:\DZNOW\api
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
run.bat
```

Ставить Visual C++ Build Tools ради одной библиотеки не нужно.

### Без бэкенда это не сломано

Если `web\.env` нет, приложение работает в режиме мока и рендера на сервере не
происходит вообще — так и задумано. «Создать» проигрывает шаги сборки, а картинка
собирается прямо в браузере, когда вы нажимаете «Скачать» на экране результата.
Признак режима видно на экране «Профиль» внизу.

### Проверить серверный рендер

```bash
curl -X POST http://127.0.0.1:8010/api/render \
  -H 'Content-Type: application/json' \
  -d '{"layout":"card","format":"png","data":{"complex":"ЖК «Панорама»","rooms":"2-комнатная","area":62.4,"floor":"9 из 17","district":"Академгородок","finish":"White box","ready":"IV кв. 2027","price":9450000,"down":20,"rate":5.9,"term":25,"tag":"Семейная ипотека 5,9%","skin":"dark"}}'
```

В ответе `{"url":"/files/dznow_....png"}` — файл 1080×1920.
`RENDER_URL` в `.env` должен указывать на живой фронт: в деве `:5173/render.html`,
в контейнере — на `127.0.0.1:8010/render.html`, потому что там собранный фронт
раздаёт сам API (`DIST_DIR` в `api/app/config.py`). Отдельный веб-сервер под
статику не нужен, и версия «что видит человек» не может разойтись с «что попало
в файл».

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | проверка живости |
| GET | `/api/me` | пользователь из initData + бренд агентства |
| GET | `/api/projects` | последние макеты пользователя |
| POST | `/api/projects` | сохранить макет |
| POST | `/api/render` | собрать PNG 1080×1920 |
| GET | `/files/{name}` | отдать готовый файл |

Авторизация — заголовок `X-Telegram-Init-Data`, подпись проверяется HMAC по `BOT_TOKEN`.
Для локальной разработки `ALLOW_DEV_NO_AUTH=1` пускает анонимного пользователя.

## Что сделано и что дальше

Готово: оба макета, каталог сценариев, редактор, экраны сборки и результата,
история с «Повторить», Telegram SDK (тема, нативная кнопка «Назад», initData),
серверный рендер PNG, SQLite-хранилище.

Дальше по порядку:

1. **Очередь рендеров** — Redis + RQ. Сейчас `/api/render` синхронный: PNG успевает,
   MP4 не успеет никогда.
2. **MP4** — покадровый рендер (Remotion либо Playwright + ffmpeg), 6–10 секунд,
   музыка из лицензированной библиотеки.
3. **Мультитенантность** — таблицы `tenants`, `memberships`, `themes`; бренд перестаёт
   быть константой в `data/brand.js` и приезжает из `/api/me`.
4. **Postgres вместо SQLite** — как только появятся параллельные рендеры и платежи.
5. **Локальные шрифты** — команда в `tools\fetch-fonts.ps1`, инструкция ниже.
6. **Третий сценарий** («Рассрочка / ипотека») — заодно замер, сколько реально
   стоит новый шаблон.

## Планировки

В макет попадает только то, что загрузил пользователь. Своих планировок
приложение не придумывает: рисовать геометрию, которой у реальной квартиры нет,
нельзя — это вводит покупателя в заблуждение.

`web/src/lib/planImage.js` превращает обычный чертёж застройщика (чёрным по белому)
в линии фирменного цвета на прозрачном фоне: контраст растягивается по гистограмме,
яркость становится альфа-каналом, поля обрезаются. Пересобирается при смене палитры,
чтобы цвет линий совпадал с макетом. В загрузчике есть второй режим —
«как есть», для цветных 3D-планов.

Чертёж почти никогда не попадает в рамку идеально, поэтому во вкладке «Дизайн»
есть посадка (`components/PlanFit.jsx`): масштаб 60–200 %, сдвиг по обеим осям
±40 % (оба ползунка в одной строке — по ряду на ось съедало полэкрана) и
плотность подложки под окном чертежа. Это `transform` у обёртки `.s-plan-fit` —
картинка не пересжимается, значения лежат в данных проекта (`planScale`,
`planX`, `planY`, `planPanel`) и уезжают в рендер.

Нет файла — блок планировки в макете не показывается, и вёрстка перестраивается:
заголовок с ценой занимают верх, факты и ипотека уходят вниз (класс `no-plan`).

Отложено: кадрирование чужой квартиры из плана этажа и разбор чертежа моделью
с перерисовкой в вектор.

## Редактор: две вкладки

«Информация» — поля объекта и загрузка планировки. «Дизайн» — палитра, шрифт,
крупность текста, фон, посадка чертежа и набор блоков. Одной простынёй это
занимало пять экранов прокрутки: чтобы поправить цену, приходилось листать
мимо всего оформления.

## Оформление

Три вещи, которыми риэлтор доводит макет до стиля агентства: палитра, шрифт и фон.
Всё живёт в блоке «Оформление» (`components/StyleStudio.jsx`), значения — в данных
проекта, то есть уезжают на сервер и попадают в файл.

**Палитра.** `lib/palette.js` строит всю схему из двух опорных цветов — фона и
акцента. Остальное (панели, основной и приглушённый текст, линии, обводка чертежа,
заливка комнат, свечение, цвет текста на акценте) выводится из них: яркость по
формуле относительной светимости, контраст проверяется по WCAG, текст на акценте
выбирается между светлым и тёмным. Поэтому чужой брендовый цвет не ломает макет —
шаблон подстраивается сам.

Три способа задать: библиотека из 10 готовых наборов (`PALETTE_LIBRARY`),
поля-пипетки для своих цветов агентства, кнопка «Случайная» — генератор в духе
[coolors.co](https://coolors.co), но с фильтром по контрасту (в прогоне 200 из 200
случайных палитр проходят проверку).

Третья пипетка — цвет подписей (`dim`): «Площадь», «Отделка», телефон, цена за
метр. Обычно он считается сам, `autoDim` дотягивает его до контраста 5,4:1 к фону
(прежняя формула давала 4,4 на части палитр, и серый плохо читался). Поверх
фотографии он дополнительно подтягивается к основному цвету. Но автоподбор не
всесилен — на пёстром снимке серый всё равно может утонуть, поэтому его можно
перебить вручную; ручной выбор отключает обе автоматики, рядом есть «Вернуть
автоподбор».

**Крупность текста** — множитель `--ts` для мелких надписей (всё, что ≤ 32 px:
подписи фактов, контакты, район, условия ипотеки). Заголовок, цена и большая
цифра не масштабируются: они и так читаются, а их рост ломает вертикальную
вёрстку кадра.

**Шрифт.** 9 пар «заголовок + текст» из Google Fonts, все с кириллицей
(`data/fonts.js`). У акцидентных — Unbounded, Oswald, антиквы — текст остаётся
нейтральным, иначе макет становится нечитаемым.

**Фон.** Фотография ЖК кладётся под макет и притеняется градиентом цвета фона:
в одном углу снимок виден почти полностью, в противоположном уходит под заливку.
Направление выбирается из четырёх углов, плотность — слайдером; на максимуме
завеса закрывает снимок полностью (раньше «самое плотное» положение всё равно
оставалось прозрачным на 5–10 %).

При включённом фоне карточки фактов становятся полупрозрачными (`.story.has-bg`),
иначе они режут снимок на прямоугольники. У окна чертежа своя ручка — «Подложка»
в разделе «Планировка»: линии плана тоньше крупных цифр и по фотографии теряются
сильнее, поэтому по умолчанию там 90 % и доступны все 100 %.

Цвета в `story.css` — только `rgba` и обычные hex. `color-mix()` и `color(srgb …)`
там запрещены: клиентский фолбэк `html2canvas` их не разбирает и падает на экспорте.

## Профиль и блоки макета

Профиль (`ProfilePage`) редактируется в приложении: имя, фамилия, телефон,
Telegram, почта, сайт, название компании, буквенный знак, фирменный цвет и логотип
картинкой. Хранится на устройстве (`lib/profile.js`), в проде приедет из `/api/me`.

До шаблонов бренд доезжает через `lib/brandContext.jsx` — превью встречаются на пяти
экранах, протаскивать логотип пропсами через все было бы шумно. Серверный рендер
оборачивает макет в тот же провайдер, получая бренд в теле запроса `/api/render`.

Что из этого показывать — решается в редакторе, блок «Что показывать»
(`components/ShowToggles.jsx`). Набор переключателей задаёт сам макет:

```js
LAYOUT_BLOCKS = {
  card:   ["logo", "agency", "tag", "author", "phone", "contacts"],
  figure: ["logo", "agency", "tag", "author", "phone"]   // строки доп. контактов нет
}
```

Флаги лежат в данных проекта (`draft.show`), поэтому уезжают на сервер вместе
с макетом и попадают в файл.

## Шрифты

Пока подключены из сети. Для рендера на сервере это риск: без интернета Chromium
молча подставит системный шрифт, и макет уедет. Переключение на локальные:

```powershell
powershell -ExecutionPolicy Bypass -File tools\fetch-fonts.ps1
```

Скрипт скачает woff2 с кириллицей в `web\public\fonts`:

| Шрифт | Начертания | Где работает |
|---|---|---|
| Onest | 400 500 600 700 800 | интерфейс, текст макетов, фолбэк для акцидентных |
| Unbounded | 600 700 | набор «Unbounded» |
| Montserrat | 400 500 600 700 800 | набор «Montserrat» |
| Golos Text | 400 500 600 700 800 | набор «Golos Text» |
| Rubik | 400 500 600 700 800 | набор «Rubik» |
| Oswald | 400 500 600 700 | заголовки набора «Oswald» |
| Playfair Display | 600 700 800 | заголовки набора «Playfair» |
| Cormorant Garamond | 600 700 | заголовки набора «Cormorant» |
| PT Serif | 400 700 | заголовки набора «PT Serif» |
| IBM Plex Mono | 400 500 | цены, платежи, площади во всех наборах |

Дальше два шага руками: раскомментировать `import "./styles/fonts.css"` в
`src/main.jsx` и `src/render-entry.jsx`, затем удалить `<link>` на
`fonts.googleapis.com` из `index.html` и `render.html` (они помечены комментарием).

Если PowerShell не пустит скрипт в сеть, те же семейства качаются руками на
<https://gwfh.mranftl.com>: выбрать subsets `cyrillic` + `latin`, формат woff2,
нужные начертания — и переименовать файлы в `onest-400.woff2`, `unbounded-700.woff2`
и так далее, как ждёт `fonts.css`.

## Заметки

- JSX компилируется встроенным в Vite esbuild, `@vitejs/plugin-react` не нужен
  (та же схема, что в вашем gacha-проекте). Понадобится Fast Refresh — ставится отдельно.
- Системная настройка «уменьшить движение» глушит автоматические анимации, но
  не нажатие «Просмотреть анимацию»: там макет проигрывается всегда.
- `prototype/index.html` — предыдущий одностраничный прототип. Ничего не требует,
  открывается двойным кликом; удобно показывать без ноутбука с Node.

**`NotImplementedError` в трейсе Playwright на Windows.**
Так выглядит попытка асинхронного Playwright запустить Chromium под uvicorn:
на Windows там `SelectorEventLoop`, который не умеет порождать процессы.
Лечится в коде — рендер работает в отдельном потоке на синхронном Playwright.
Если увидели это снова, значит `api\app\render.py` старой версии.

**`Executable doesn't exist` в ответе рендера.**
Не докачался браузер: `python -m playwright install chromium`.
