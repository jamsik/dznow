# Развернуть DZNOW на сервере

Цель: открыть приложение из Telegram по кнопке бота и дать потыкать
нескольким людям. Продакшеном это ещё не будет — в конце написано, чего
для него не хватает.

## Что получится

```
Telegram ──кнопка бота──► https://ваш-адрес ──► контейнер dznow-app
                                                 ├── приложение (собранный фронт)
                                                 ├── /api — проекты, рендер
                                                 └── Chromium, снимает PNG 1080×1920
                          контейнер dznow-bot ──► показывает кнопку, больше ничего
```

Два контейнера в своём compose-проекте `dznow`. Соседний бот, который у вас
уже работает, они не трогают: другие имена, другие тома, другой образ.
Наружу торчит только адрес, который вы выберете на шаге 3.

**Где авторизация.** Отдельной регистрации нет и не будет. Telegram, открывая
Mini App, передаёт в неё подписанную строку `initData`; API проверяет подпись
HMAC по токену бота (`api/app/auth.py`) и достаёт оттуда, кто пришёл. Поэтому
токен бота — это и есть ключ авторизации, и поэтому анонимный вход
выключается сам, как только `BOT_TOKEN` появился в окружении.

---

## Шаг 1. Бот

В Telegram напишите [@BotFather](https://t.me/BotFather):

```
/newbot
```

Он спросит имя (любое, например `DZNOW`) и username — он должен заканчиваться
на `bot`, например `dznow_test_bot`. В ответ придёт токен вида
`8123456789:AAH...` — это пароль от бота, его нельзя публиковать и нельзя
коммитить.

Больше в BotFather ничего настраивать не нужно: кнопку меню бот пропишет себе
сам при первом запуске.

## Шаг 2. Положить код на GitHub

На вашем компьютере, в обычной командной строке. Если git не стоит:

```bat
winget install Git.Git
```

После установки закройте и откройте окно командной строки заново — иначе
`git` не найдётся в PATH.

```bat
cd F:\DZNOW
git init -b main
git add .
git commit -m "DZNOW: Mini App, рендер PNG, деплой в Docker"
```

Теперь заведите пустой репозиторий на <https://github.com/new>: имя `dznow`,
публичный, **без** галочек «Add a README», «Add .gitignore», «Choose a license» —
иначе первый `push` упрётся в конфликт. И свяжите:

```bat
git remote add origin https://github.com/ВАШ_ЛОГИН/dznow.git
git push -u origin main
```

При первом `push` откроется окно входа в GitHub — войдите браузером.

Токен бота в репозиторий не попадёт: он живёт в `.env`, а `.env` перечислен
в `.gitignore`. Проверить, что ничего лишнего не уехало, можно так:

```bat
git ls-files | findstr /i ".env"
```

Должно найтись только `.env.example` — файл с пустыми значениями.

## Шаг 3. Поднять на сервере

Сервер уже разведан: Ubuntu, Docker, nginx **на хосте** (не в контейнере) держит
80 и 443, соседний проект `friends-gacha` опубликован на `127.0.0.1:8000` и
описан в `/etc/nginx/sites-enabled/friends-gacha`. Порт 8010 свободен.

Значит, схема ровно та же, что у соседа: контейнер слушает локальный порт,
наружу выпускает nginx. Ничего нового открывать не нужно, и `friends-gacha`
не затрагивается — у DZNOW свой файл сайта, свой compose-проект, свои тома.

```
              ┌── nginx (хост, :80 :443) ──┐
интернет ─────┤                            ├── 127.0.0.1:8000 → friends-gacha
              └────────────────────────────┴── 127.0.0.1:8010 → dznow (новый)
```

### 3.1. Поддомен

Нужна A-запись `dznow.ВАШДОМЕН` → IP этого сервера, в панели регистратора.
Проверить, что разошлась: `dig +short dznow.ВАШДОМЕН` должен вернуть тот же IP,
что `curl -s ifconfig.me` на сервере.

Если добавить запись нельзя, DZNOW можно повесить путём на существующий домен
(`https://домен/dznow/`) — Mini App так тоже работает, но придётся собрать фронт
с `base: "/dznow/"` в `vite.config.js`. Поддомен проще, начните с него.

### 3.2. Контейнеры

```bash
cd /opt
git clone https://github.com/ВАШ_ЛОГИН/dznow.git
cd dznow
cp .env.example .env
nano .env
```

В `.env` заполнить три строки (`APP_DOMAIN` нужен только профилю caddy, его
здесь не используем — оставьте пустым):

```
BOT_TOKEN=8123456789:AAH...
APP_URL=https://dznow.ВАШДОМЕН
BOT_USERNAME=dznow_test_bot
```

```bash
docker compose up -d --build
docker compose ps          # app healthy, bot running
curl -s localhost:8010/api/health    # {"ok":true}
```

Первая сборка небыстрая: внутрь образа ставится Chromium.

### 3.3. nginx

В репозитории лежит готовый файл — в нём поменять `dznow.ВАШДОМЕН` на свой
поддомен и положить на место:

```bash
sudo cp deploy/nginx/dznow.conf /etc/nginx/sites-available/dznow
sudo sed -i 's/dznow.ВАШДОМЕН/dznow.вашдомен.ru/' /etc/nginx/sites-available/dznow
sudo ln -s /etc/nginx/sites-available/dznow /etc/nginx/sites-enabled/dznow
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` обязателен: с ошибкой в конфиге nginx не перезапустится и уронит
заодно соседний сайт. Пока `-t` не сказал `syntax is ok`, `reload` не делать.

Сертификат:

```bash
sudo certbot --nginx -d dznow.вашдомен.ru
```

Certbot сам допишет в файл блок `:443` и редирект с `:80`. Если certbot не
установлен — `sudo snap install --classic certbot`.

### 3.4. Запустить бота

Бот стартует вместе со всеми, но `APP_URL` он читает при старте — если вписали
его после первого `up`, перезапустите:

```bash
docker compose up -d bot
docker compose logs bot   # «бот @… запущен, приложение: https://…»
```

### Если поддомена не будет

В `docker-compose.yml` остались два профиля на этот случай — Caddy со своим
доменом и Cloudflare-туннель без домена вообще. Для вашего сервера они не
нужны: Caddy подрался бы с nginx за порты 80 и 443.

## Шаг 4. Проверить

```bash
docker compose ps          # оба контейнера running, app — healthy
docker compose logs -f bot # в логе: «бот @… запущен, приложение: https://…»
```

В Telegram откройте своего бота, отправьте `/start` и нажмите «Открыть DZNOW».
Заполните поля, нажмите «Создать» — должен прийти PNG 1080×1920.

Если открыть тот же адрес в обычном браузере, приложение честно скажет
«Откройте через Telegram»: вне Telegram нет подписи, и сервер не знает, кто вы.
Это не поломка.

**Первый рендер медленнее остальных** — контейнер поднимает Chromium. Дальше
браузер остаётся в памяти и следующие макеты собираются быстро.

## Обновить после правок

На компьютере:

```bat
cd F:\DZNOW
git add .
git commit -m "что поменяли"
git push
```

На сервере:

```bash
cd dznow
git pull
docker compose up -d --build
```

Проекты и готовые файлы лежат в томе `dznow-data` и пересборку переживают.

## Чего не хватает для настоящего продакшена

Это честный список, а не придирки — просто на тестах оно не мешает.

1. **SQLite и один рендер за раз.** Сейчас макеты собираются по очереди в одном
   потоке. Два человека нажали «Создать» одновременно — второй ждёт. Лечится
   очередью (Redis + RQ) и Postgres; оба пункта уже стоят в плане в README.
2. **Файлы копятся вечно.** `/data/files` никто не чистит. До первых сотен
   картинок это неважно, дальше нужна уборка по возрасту.
3. **Бренд агентства — константа** в `api/app/main.py`. Под нескольких клиентов
   нужна таблица арендаторов, это тоже в плане.
4. **Шрифты тянутся из сети** при каждом рендере. Если у сервера пропадёт доступ
   к `fonts.googleapis.com`, Chromium молча подставит системный шрифт и макет
   уедет. Лечится складыванием шрифтов в образ — `tools/fetch-fonts.ps1`
   и раздел «Шрифты» в README.
5. **Нет бэкапа.** Том `dznow-data` стоит забирать `docker run --rm -v
   dznow-data:/d -v $PWD:/out alpine tar czf /out/dznow-data.tgz -C /d .`
