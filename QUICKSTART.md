# Локальный запуск DZNOW

Два окна командной строки: в одном фронтенд, в другом сервер.
Фронтенд самодостаточен — сервер нужен только ради настоящего PNG.

---

## Окно 1. Фронтенд

```bat
cd F:\DZNOW\web
npm install
npm run dev
```

Открыть <http://127.0.0.1:5173>.

Здесь уже всё работает: главная, редактор, сборка, результат, «Мои дизайны».
Проекты хранятся в браузере, картинка собирается на устройстве.
Внизу экрана «Профиль» написано, в каком режиме приложение сейчас работает.

**На этом можно остановиться,** если сегодня нужно просто посмотреть и показать.

---

## Окно 2. Сервер (настоящий рендер PNG)

```bat
cd F:\DZNOW\api
pip install -r requirements.txt
python -m playwright install chromium
run.bat
```

Проверка: <http://127.0.0.1:8010/api/health> отдаёт `{"ok":true}`.

Окно 1 при этом должно остаться запущенным: рендер открывает страницу фронтенда
в отдельном Chromium и снимает её. Без работающего фронта рендерить нечего.

`.env` не нужен: пока `BOT_TOKEN` пуст, вход анонимный, а адрес фронта берётся
по умолчанию. Понадобится поменять — `copy .env.example .env`.

---

## Шаг 3. Соединить фронт с сервером

```bat
cd F:\DZNOW\web
copy .env.example .env
```

Перезапустить `npm run dev` — Vite читает `.env` только при старте.

Теперь при нажатии «Создать» макет уходит на сервер, а «Скачать» открывает файл
из `F:\DZNOW\api\data\files`. Проекты тоже начинают жить на сервере,
в `F:\DZNOW\api\data\dznow.db`.

---

## Что где лежит

| Путь | Что это |
|---|---|
| `web\src\templates\` | сами макеты 1080×1920 |
| `web\src\pages\` | экраны приложения |
| `web\src\data\catalog.js` | сценарии, шаблоны, значения по умолчанию |
| `api\data\files\` | отрендеренные PNG |
| `api\data\dznow.db` | сохранённые макеты |
| `prototype\index.html` | старый одностраничный прототип, открывается двойным кликом |

## Если что-то не пошло

**`pip` падает на greenlet, просит Visual C++.**
Python 3.14 слишком свежий для этой библиотеки. Сначала `pip install -r requirements.txt --upgrade`.
Если не помогло — отдельное окружение на 3.12, система при этом не трогается:

```bat
winget install Python.Python.3.12
cd F:\DZNOW\api
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
run.bat
```

**`Copy-Item is not recognized`** — это команда PowerShell. В обычной командной
строке `copy`, в PowerShell `Copy-Item`.

**Приложение открылось, но «Скачать» даёт картинку без сервера.**
Значит `web\.env` не создан или `npm run dev` не перезапущен после его создания.

**Рендер на сервере отвечает ошибкой.**
Проверьте, что окно 1 живо и `RENDER_URL` (по умолчанию `http://127.0.0.1:5173/render.html`)
открывается в браузере — там должен быть виден один макет во весь экран.

**`NotImplementedError` в трейсе Playwright на Windows.**
Так выглядит попытка асинхронного Playwright запустить Chromium под uvicorn:
на Windows там `SelectorEventLoop`, который не умеет порождать процессы.
Лечится в коде — рендер работает в отдельном потоке на синхронном Playwright.
Если увидели это снова, значит `api\app\render.py` старой версии.

**`Executable doesn't exist` в ответе рендера.**
Не докачался браузер: `python -m playwright install chromium`.

**Порт занят.** 5173 меняется в `web\vite.config.js`, 8010 — в `api\run.bat`
(и тогда же в `proxy` внутри `vite.config.js`).
